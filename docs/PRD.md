## 1. 产品概述

### 1.1 产品定位
面向 Windows 桌面平台的专业级本地电子书阅读器，以静读天下专业版为核心对标基准，完整复刻其深度阅读、高度自定义、全格式兼容的核心优势，同时结合 PC 端大屏显示、键鼠操作、多任务并行、系统深度集成的特性，打造「格式全覆盖、排版千人千面、阅读沉浸专注、管理一体化」的桌面端深度阅读工具，覆盖**电子书休闲阅读、专业文献学习、数字藏书管理**三大核心场景。

### 1.2 目标用户群体
- 深度阅读爱好者、网络文学长期读者，追求极致排版与沉浸式阅读体验
- 学术文献、专业书籍学习者，PDF/EPUB 重度用户，需标注、笔记、翻译等学习功能
- 电子书收藏与整理爱好者，需大规模书籍分类、管理、备份能力
- 职场办公人群，需碎片化阅读文档、批注资料、跨设备同步阅读进度

### 1.3 核心设计原则
1. **格式兼容优先**：100% 覆盖静读天下专业版支持的所有文件格式，无需转换即可原生读取
2. **体验对齐 + 平台增强**：核心阅读逻辑对齐安卓端操作习惯，针对键鼠、多屏、窗口化等 PC 特性做体验升级
3. **高度可定制**：保留静读天下「像素级可调」的排版自定义能力，参数精度与专业版保持一致
4. **性能轻量化**：大文件秒开、低内存占用、后台无冗余进程
5. **数据可迁移**：兼容静读天下的备份格式与同步协议，支持安卓→Windows 无缝迁移

## 附录 A：功能融合规划（V1.1 增补，2026-09-12）

> 本附录为产品级约束，优先级高于正文各功能条目的实现方式。正文是"做什么"，本附录是"怎么组织才不臃肿"。

### A.1 背景与问题
- 旧项目（本地书库 v1.0→v2.17.5）按**技术手段**堆功能（智能爬取、联网补全、AI 查找、本地比对修正、封面下载、标签分类各自独立入口），导致功能臃肿、交互分散、维护成本高。
- 本 PRD 功能量极大（40+ 格式、PDF 专业、云同步、应用锁、插件、20+ 语言），若逐条铺开必然重蹈覆辙。
- **根因**：功能按"怎么做"组织，而不是按"用户要什么"组织。

### A.2 融合原则
1. **按用户意图组织，不按技术手段堆砌**：入口命名用用户语言（"智能整理"），不用技术名词（"爬取/补全/对比"）。
2. **一个意图 = 一条流水线 = 一次交互**：多个技术步骤收敛到一个入口，自动执行 + 一次确认。
3. **新功能先归位、再排期**：任何新增功能必须先映射到四大能力中心之一，禁止新增散落按钮/设置项。
4. **数据只存一份**：一本书只有一个元数据记录、一个进度、一套标注；融合功能共享同一数据源，不做各自数据库。

### A.3 四大能力中心（功能归位矩阵）
| 能力中心 | 用户意图 | 吸收融合的功能（PRD 章节） | 交互形态 |
| --- | --- | --- | --- |

### A.4 融合示例：元数据智能中心（旧项目 6~7 个入口 → 1 条流水线）
```
扫描/导入 → 文件名+正文首段提取候选书名
→ 置信度判定（书名完整/疑似有误）
→ 高置信：直接入库；低置信：进入「待确认」列表
→ 一键联网比对（多书源 + 可选 AI 二次确认）
→ 补全简介/封面/作者/标签
→ 一次确认后落库
```

### A.5 落地路线
- **M1（已完成）**：格式解析中心已按 `IBookParser` 统一落地（TXT/EPUB/MOBI）。
- **M2 第一步**：实现元数据智能中心「智能整理」流水线（吸收旧项目全部爬取/补全/修正功能为一步）。
- **M2 后续**：内容体验中心融合（进度↔听书互通、标注整合）；系统服务中心统一设置面板。
- **M3**：格式解析中心扩展 PDF/漫画；云同步/备份归入系统服务中心。

### A.6 验收口径
- 核心功能 3 步内可达（对齐 PRD 6.4）。
- 书架页功能按钮 ≤ 8 个（含搜索/导入/智能整理/视图切换），超出需先归位再实现。
- 设置面板按分类组织，禁止顶层散落开关。
